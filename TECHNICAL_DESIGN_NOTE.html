2. Database Schema & Relational Integrity

All core relationships are managed through Prisma ORM with strict referential constraints:

  • Compound Unique Constraint: Engagement: @@unique([clientId, serviceTypeId, period]) strictly guarantees that duplicate recurring engagements cannot be created for the same client, service, and period.
  • Referential Actions: Deleting a client is protected with onDelete: Restrict. Deleting an engagement cascades cleanly to its child tasks and audit log entries (onDelete: Cascade).
  • Performance Indexes: Added indexes on Task(assignedToId), Task(status), Task(dueDate), and TaskAuditLog(taskId).

3. Task Workflow Finite State Machine (FSM)

Task lifecycle transitions strictly enforce organizational governance and prevent unauthorized status progression:

[NOT_STARTED] ──> [IN_PROGRESS] ──> [READY_FOR_REVIEW] ──> [COMPLETED] (Manager Only!)
                        │                   │
                        ▼                   ▼
              [WAITING_FOR_CLIENT]   [CHANGES_REQUESTED]
                        │                   │
                        └──> [IN_PROGRESS] <──┘

FSM Transition Governance Rules

Transition Allowed Roles Validation / Pre-conditions
NOT_STARTED → IN_PROGRESS Assigned Member, Manager, Admin Marks task execution commencement.
IN_PROGRESS → WAITING_FOR_CLIENT Assigned Member, Manager, Admin Client input or documentation requested.
WAITING_FOR_CLIENT → IN_PROGRESS Assigned Member, Manager, Admin Client provided required information.
IN_PROGRESS → READY_FOR_REVIEW Assigned Member, Manager, Admin Work submitted for management audit.
READY_FOR_REVIEW → CHANGES_REQUESTED Manager, Admin (Team Member Forbidden) Mandatory review feedback notes required.
READY_FOR_REVIEW → COMPLETED Manager, Admin (Team Member Forbidden) Self-approval rejected! Prevents specialists from approving own work.

4. Authentication, Authorization & Roles

Role Permissions & Capabilities
ADMIN Full system control, manage clients, configure service templates, view all engagements, override task assignments and workflows.
MANAGER Create engagements, generate recurring periods, assign/reassign tasks, review and approve work, request changes with feedback notes.
TEAM_MEMBER View assigned tasks, advance work to in-progress, flag waiting for client, submit work for review. Cannot self-approve or reassign other members' tasks.

6. Production Scaling Strategy (5 Million Tasks)

  • Partitioning & Partial Indexes: Range partitioning by created_at; partial indexes on WHERE status != 'COMPLETED' for fast operational queries.
  • Cursor-based Pagination: Keyset pagination on (due_date, id) eliminating expensive SQL OFFSET queries.
  • Distributed Background Queues: Offloading recurring period roll-overs to BullMQ / Redis queues with automatic retries and dead-letter queues.
  • Metric Caching: Real-time aggregate count caching in Redis with atomic increments (HINCRBY) on status transitions.
